# Google Flow prompt recipes (manual generation — no API)

Flow (flow.google) has no public generation API. Every still and clip below
is generated by the **user**, by hand, inside Flow's browser UI. Your job
in this pipeline step is always the same three-part move:

1. Write the complete prompt (copy-pasteable, no placeholders left in it).
2. Say exactly which Flow tool to use (Nano Banana for stills, Veo 3.1
   image-to-video for clips) and, for clips, which file to use as the
   starting frame.
3. **Stop.** Wait for the user to come back with the downloaded file. Don't
   write the next prompt, don't guess what the result looks like, don't
   move on until the file is in hand.

## Hero still (the anchor — everything inherits from it)

Include, always: product description with materials/accents · composition
("centered, generous empty space around it") · backdrop ("deep black /
dark charcoal studio background") · lighting ("dramatic <accent> rim
light, soft key light") · "photorealistic 8k commercial product
photography". Bake in props future chapters need (a glass, a visible
pipe, room above for falling objects). Front-on symmetric compositions
survive video generation best; three-quarter has more character but
drifts more.

Ask for 2-3 variations in one Flow session if the UI allows it (cheap,
worth the iteration) — otherwise write 2-3 separate prompts and let the
user run them one at a time.

Image models invent fake logos/text — once the file comes back, inspect
zoomed crops and patch with Pillow before it's used as a video input
(clone a clean band from the same surface with a feathered mask, keeping
the artifact fully inside the solid mask zone; match per-row brightness).

## Clip prompt skeleton (Veo 3.1 image-to-video)

```
<one specific action, slow motion> + <what stays unchanged: "the machine
stays perfectly still and unchanged, dark studio background unchanged,
studio lighting unchanged"> + "locked static camera, no camera movement"
```

Veo 3.1 also generates native synced audio — if the site doesn't want
sound, tell the user to mute/strip it on download (`ffmpeg -an` when the
clip is processed), otherwise it carries through into the master film.

Flow's UI may not expose a separate negative-prompt field the way Kling's
API did — fold exclusions into the main prompt instead ("no camera
movement, no morphing, no duplicate objects, no extra objects appearing,
no hands, no people, no text or watermark or logo, no background change")
rather than assuming a dedicated field exists. Confirm what Flow's current
interface offers and adjust.

## Recipes to hand the user

- **Assembly (reverse trick)** — prompt: "Product explosion animation: the
  X completely disassembles, every component detaches and flies slowly
  apart, <list its parts>, by the final frame the X is fully taken apart
  into dozens of individual floating parts with large gaps of empty space
  between them, exploded view product animation, slow motion, locked
  static camera, no camera movement, no morphing, no duplicate objects."
  Starting image: the hero still. Once the file is back, reverse it
  yourself (`ffmpeg -vf reverse`) — it then ends pixel-perfect on the hero.
  The explicit final-frame sentence is what makes the model commit; without
  it the explosion tends to stay timid and drift back together.
- **360 rotation** — prompt: "rotates slowly and smoothly a full 360
  degrees around its vertical axis while floating in dark space, <accent>
  rim light sweeps across as it turns, constant smooth turntable rotation,
  stays centered and level, locked static camera." Starting image: the
  hero. A glowing floor ring may appear uninvited — usually looks great,
  keep it.
- **Liquid pour / fill** — prompt: "a slow steady stream of X pours into
  the empty glass, gradually fills with <texture detail>, faint wisps of
  steam, locked static camera, no camera movement." Starting image: an
  extracted frame where the vessel is empty (chain the *last frame* of the
  prior clip into this one so state carries forward).
- **Steam / atmosphere** — prompt: "dense white steam gently rises from X,
  curling and drifting upward in slow motion, warm rim lighting catches the
  wisps, locked static camera."
- **Power-up / fire** — prompt: "the <accent> ring ignites and glows, a
  brief elegant burst of white light, locked static camera" — good for
  shutters, buttons, activations.
- **Final hero** — starting image: the last state frame in the sequence.
  Prompt: "studio lighting slowly blooms warmer and richer, details
  glint, very slow smooth subtle camera push-in" — the one clip where
  gentle camera motion is allowed.
- **Macro/keyframe stills for non-product chapters** (falling beans,
  sensors, exploded stacks, wireframes): generate these as stills directly
  in the same lighting language; they don't need product consistency, so
  they're a good place to burn fewer generations.

## Known failure patterns to watch for

These were documented on the previous Kling-based pipeline — Veo 3.1 may
behave differently. Treat as things to check for on the first few clips of
a build, not settled fact:

- Complex multi-part products (shoes, multi-piece assemblies) may
  DUPLICATE instead of separating on explosion/exploded-view prompts —
  after two failed attempts, switch to the sliced-still + GSAP strips
  technique (see `gsap-nextjs.md`), which is fully controllable and
  doesn't depend on video generation at all.
- Liquid/state resets across chapter cuts — chain last-frames, order
  chapters to minimize resets, and let the 0.4s xfades + captions mask
  the rest.
- Output aspect ratio likely follows the input still's aspect, as it did
  on Kling — keep all anchor stills one consistent aspect ratio (16:9 or
  4:3) across a project so clips match without extra normalization work.

## QC every clip before using it

Once a clip file is back from the user, before treating it as usable:

```bash
n=$(ffprobe -v error -select_streams v -count_frames -show_entries stream=nb_read_frames -of csv=p=0 clip.mp4)
ffmpeg -y -v error -i clip.mp4 -vf "select='eq(n\,0)+eq(n\,$((n/4)))+eq(n\,$((n/2)))+eq(n\,$((3*n/4)))+eq(n\,$((n-1)))',scale=460:-1,tile=5x1" -frames:v 1 sheet.png
```

Look for: morphing, duplicates, background/lighting shifts, camera drift,
unwanted audio. If it fails, rewrite just that one prompt and send the user
back to regenerate — never the whole set.
